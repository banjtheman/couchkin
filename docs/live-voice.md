# OpenAI live voice

Couchkin's live mode uses **GPT-Live (`gpt-live-1`)**, Marin by default, with a Responses backend for game context and tools. Live voice and backend usage are billed to your OpenAI API account; a ChatGPT subscription does not cover those calls. Codex is optional for original artwork and the earlier Mac voice + Codex mode.

## Set up

1. Keep `OPENAI_API_KEY` in the Couchkin project's private `.env` or a `.env` in Electron's application-data directory, then restart Couchkin. An environment variable also works and takes precedence. Only the desktop main process reads the key; it is not copied into settings, the renderer, or the OBS overlay.
2. Under **Your companion → Speaking voice**, choose **OpenAI live voice** and a voice. Changing the voice, game title, or OBS source pauses live mode and closes the old connection. The game title saves on Enter or when you leave the field, rather than on every keystroke. Click **Start session** to use the new context.
3. In **Connections**, use **Check microphone permission** and answer the macOS prompt. This works before a paid voice session and does not start capture. Then connect live voice, connect OBS, select the original game input, and add the overlay. Twitch chat is optional.
4. On **On the couch**, choose your **Microphone**. **System default** follows the Mac's default input; choose a named device such as Blue Snowball to use that input specifically. This choice is separate from OBS and is remembered on this Mac. Start a session, then **Enable live mic** when ready to speak. The opened device's name and level meter help confirm the source. Changing the selected device while listening reconnects capture to that device. A disconnected selected input requires your attention instead of silently falling back to another mic. Use **Look at the game** for a current frame; a manual look requires an active session and does not silently reconnect a paused one. The mic sends audio to OpenAI continuously while enabled, including quiet moments. Turning it off, pausing, disconnecting, or leaving the session page stops capture.
5. Use headphones. When the OBS overlay owns playback, enable **Monitor and Output** for the Couchkin source if you want to hear Pip locally. Avoid capturing the monitored audio again through desktop audio.

The local `.env` is ignored by Git and excluded from the packaged app. A standalone Mac installation can use its application-data `.env` (normally `~/Library/Application Support/Couchkin/.env`). Each machine needs its own key. Do not paste it into a chat, commit it, or include it in a screenshot.

## Context and tools

Pip's voice uses the selected character's personality, spoiler preference, current game title, recent conversation, Twitch chat, and existing local memories. With **Remember shared moments** enabled on **Shared memories**, Live mode checks settled direct dialogue for a few useful game preferences and streamer-confirmed moments. This separate background request does not block voice; it starts at most once every 45 seconds and may finish after an explicit Pause. Add a note manually or forget one on the same page. Selected dialogue is sent to OpenAI for extraction, and only accepted short notes are stored locally. See [memory behavior and limits](memories.md). Selected game frames and context go to OpenAI for understanding; screen sampling is not continuous video.

The backend can get the latest selected OBS game image, read current stream context, change Pip's expression, and search the web for game information. Screen content, Twitch messages, and retrieved pages are evidence, not instructions that can grant new permissions. Couchkin's tools do not start a broadcast, control gameplay, or post to Twitch.

Automatic watching now uses a separate Responses observer to produce a short factual summary and, only for a meaningful new moment, an optional reaction. Summaries enter GPT-Live as quiet context through `session.thinking.append`; a selected reaction uses `session.commentary.append`. A 20–60 second cooldown, scaled by talkativeness, limits reactions. They are suppressed for five seconds after recent human speech and while Pip is speaking or the conversation backend is working. Byte-identical automatic frames are skipped. Real API and short packaged-app checks verified quiet ordinary frames followed by correct answers to explicit questions. The subsequent October 30 gameplay rehearsal exposed stale visual context and a connection loss; the changes below address freshness and diagnostic coverage.

While the mic is enabled, the first recognized speech fragment after a 1.2-second speech gap now triggers a priority screen refresh. It can run while Pip or the conversation backend is busy. Fragments within the same burst coalesce; newer speech cancels older observation work and queues one latest refresh. These speech refreshes supply quiet context and never request a spoken reaction. They start after transcript recognition, not at the physical onset of speech. A fresh summary may still arrive after Pip has begun answering, so this is an early refresh rather than a guarantee of synchronized video.

Frame timestamps now belong to individual capture requests, separately from polling attempts. They use the time the OBS screenshot was requested, conservatively including response delay; OBS does not supply an exact game-frame timestamp. Typed questions reuse a frame only within two seconds; otherwise the backend must obtain fresh evidence when the question needs it. Completed visual summaries older than six seconds are discarded, and unsolicited reactions require frames no more than four seconds old. Pausing, changing the game/source, or a newer refresh invalidates older work. Timing limits bound what Couchkin submits; they do not establish when the voice model uses it or when playback occurs.

The conversation shows transcripts. Captions follow streamed speech, and the audio player determines whether Pip is speaking. **Quiet** or Escape stops playback, closes the live connection, and pauses the session so automatic watching cannot reconnect it. Pause also closes the paid voice session and stops capture. Typed messages and conversation suggestions require an active Live session; they do not implicitly open a paid connection from an idle, paused, or failed session. Click **Start session** to resume.

## If a session stops

If typing works but Pip does not hear you, check **On the couch → Microphone** and its level meter. OBS can hear a different device than Couchkin. Refresh the input list after connecting a USB microphone, select it, and enable the mic. Device discovery does not start capture. If macOS has not granted access, use **Connections → Check microphone permission** first. A listening indicator confirms audio frames are arriving; the level meter and a transcribed spoken phrase verify that those frames contain your voice.

The status panel on **On the couch** keeps the connection's reason visible and offers a resume action. Routine state reads and overlay reconnection preserve that reason. A microphone setup failure has its own message; when the live connection remains active, the UI says so and you can continue typing.

For later diagnosis, the app keeps the latest 100 connection events in `runtime/connection-events.json` inside Electron's application-data directory. Only timestamps, component/state codes, close codes, and intentional-stop flags are saved. Chat, audio, images, keys, and raw API errors are excluded. The reported roughly four-minute stop predates these diagnostics, so its cause has not been established.

Additional metadata is saved privately in `runtime/live-diagnostics.json`, capped at 500 records with a bounded 128-record pending queue. Transport failures include allowlisted error categories, the rejected command's type when identifiable, elapsed time, last-event age, buffer bytes, and pending counts. Observation records distinguish capture, interpretation, and context submission and include timing/outcome, safe error categories, HTTP status, or known transport codes. `submitted` means locally sent for processing, not acknowledged, used by the model, or heard. These records contain no raw errors, event IDs, chat, audio, images, credentials, or source names.

## Audio path

Microphone → local PCM conversion at 24 kHz → desktop IPC → GPT-Live WebSocket. Returned PCM goes to one audio owner: OBS when its overlay is connected, otherwise the desktop player. A silent overlay preview does not claim audio.

The API key stays in the desktop process. Microphone audio is streamed without saving a recording. Capture starts only after you explicitly enable it. The UI shows cumulative voice seconds and reasoning tokens; final usage is confirmed only when the service closes the session cleanly. A connected session can incur usage while waiting, including when the mic is off; pause or disconnect when finished.
